### P1: Uniformity and orthogonality

| # | Finding |
|---|---|
| B1 | **The whole `std::vector`/`std::string` API leaks through** (`.size()`, `.length()`, `.substr()`, `.back()`, `.empty()`, `.push_back()`). This contradicts the CF-059 "single canonical method" rule: `s.find` is rejected but `s.size()`/`s.length()` are accepted, and examples use `.size()` and `.capacity()`. Fix: whitelist method calls per builtin type against the stdlib metadata table (CF-117) and add `DEPRECATED-API` fix-its. A2 is fixed as a side effect. |
| B2 | **Slicing semantics are inconsistent.** `xs[i]` panics out of bounds, but `xs[1..10]` clamps silently, `xs[2..1]` returns empty, and `"ab"[0..4]` returns `"ab"`. Byte slicing can split UTF-8 (`"héllo"[0..2]` gives `h\xC3`). Pick one rule: panic on bad ranges, and either add a char-boundary check or document byte semantics. |
| B3 | **Separator rule (ADR Q3) isn't followed for type-level statics.** The ADR reserves `::` for type paths, yet `http.Response.json(...)` / `.text(...)` use `.` (10 uses in examples/guide). Patterns use unqualified `Circle(r)` while construction requires `Shape::Circle`. Decide and lint. |
| B4 | **Constructor naming is mixed.** `make_*` is dominant, but there's `new_mutex()`, `new_app()`, the untyped `sync.Mutex` beside the data-bearing `Mutex[T]`, and `connect`/`dial`/`connect_tcp`. TLS has both a `verify_peer` flag and `connect_insecure`, two ways to do one thing. |
| B5 | **Too much type checking is delegated to clang.** Argument types, struct-field init types, unknown fields and methods, and optional arithmetic (`i32? + 1`) surface as `cfire/TYPE-ERROR` with C++ text (`const char[2]`, "member subobject"). That is the leak CF-108 meant to prevent. `if x` with `x: i32` is accepted. |
| B6 | **Inference gaps on stdlib calls.** `req.param(..)` and `server.port()` give `UNKNOWN-TYPE` warnings, including in canonical `examples/11` (the zero-warning policy is violated). Sema keeps two parallel inference paths (`infer_expr_type_name_sema` → string, `infer_expr_type_id_sema` → TypeId, `fn_checker.hpp:609`); finishing CF-116 means deleting the string path. |
| B7 | **Field capitalization means nothing.** Examples use Go-style `Title`/`Entries` but there's no visibility (`pub` deferred, CF-138). Pick a style and let `fmt`/lint enforce it. |
| B8 | **No block comments** (`/* */` is a parse error at the `/`). That's fine as a choice, but it's undocumented and the error message is poor. |

### P1: Security

| # | Finding |
|---|---|
| D1 | **The HTTP server is serial with no per-connection read timeout** (`http.hpp:1348`). One idle client blocks every other client. Invalid `Content-Length` becomes `0` (`value_or(0)`), short bodies are accepted silently, duplicate CL headers overwrite each other, bare-LF headers are accepted, and server-side `Transfer-Encoding: chunked` is ignored. That's a smuggling/desync surface if keep-alive ever lands. |
| D2 | **An in-band header disables TLS verification.** `x-cfire-tls-verify: false` in `extra_headers` turns off peer verification (`http.hpp:653,833`), and `x-cfire-tls-ca` swaps the CA. Any code that forwards user-supplied headers lets an attacker downgrade TLS. Move this to a typed options struct. |
| D3 | **Dependency cache is trusted without verification.** A git cache hit returns the existing HEAD without comparing it to `build.lock` (`deps.hpp:120`). An archive cache hit (a non-empty dir) skips the SHA-256 check. Integrity is TOFU-only when no hash is given. When `$HOME` isn't writable, the fallback cache is the shared, predictable `/tmp/cfire_cache/pkg`, so a local attacker can poison builds. `git clone`/`checkout` have no `--` separator, so a URL or ref starting with `-` is option injection. `curl` lacks `--proto =https`. |
| D4 | **Predictable `/tmp` names, no `O_EXCL`:** `/tmp/cfire_{jpg,ocr,pdf}_<pid>_<seq>` hold user documents (`vision.hpp:288,365`, `doc_pdf.hpp:389`), plus fixed `cfire_mcp_cache` / `cfire_doc_cache`. Use `mkstemp`/`mkdtemp` under a per-user dir. |
| D5 | **The `SHELL-INJECTION-RISK` lint is purely syntactic and only a warning.** It's bypassed via `cmd := "ls " + user; os.exec(cmd)` or a helper function. Taint through locals and returns, or make `os.exec` take only literals. |
| D6 | **The MCP server has no workspace confinement.** `cfire_check`, `cfire_test`, and `cfire_rename` take arbitrary paths, and `cfire_eval` runs code. That's intentional for agents, but root it at the workspace and document the trust model. `ssh.dial` defaults `user = "root"`. macOS `keychain.set` deletes before adding, so a failed add loses the secret. |
| D7 | **No client-IP API:** `TcpConn` endpoint is hard-coded to `"127.0.0.1"` on every accept (`tcp.hpp:451,464`), and the server is IPv4-only. You can't do logging, rate limiting, or allowlists. |

### P1: Concurrency safety

| # | Finding |
|---|---|
| G1 | **Data races through captured pointers are accepted.** `p := &mut counter` with 8 `scope.spawn` tasks doing `*p += 1` passes `check`. TSan reports a data race, and the result was wrong under TSan (400000 vs 800000). ESCAPING-CAPTURE-MUT covers by-value captures only, so there's no Send/Sync-style rule for pointers, views, or `shared[T]`. (Example 04's disjoint `&mut codes[i]` slots are safe, which a rule must still allow.) |
| G2 | **The documented `mu.with_lock(\|\| { count += 1 })` pattern is rejected** (ESCAPING-CAPTURE-MUT) as soon as it's used inside `spawn`, which is the only place it matters. The working pattern (`mut g := mu.lock(); *g += 1` on `Mutex[T]`) isn't documented at all: the reference only lists methods of the untyped `Mutex`. Verified correct: atomic, `Mutex[T]`, and channel fan-in give exact counts under 8×10k contention. |
| G3 | **There's no `--sanitize=thread` mode** (`buildsys.hpp:979` and `pch.hpp:138` hard-code address,undefined). |

### P1: No language-expectation conformance corpus

What exists today:
- `tests/e2e/test_canonical.cpp` runs examples 01–17 and substring-matches stdout and generated C++.
- 5 golden codegen snapshots and 10 parse-fail files.
- 39 GUIDE doc-tests.
- `tests/stdlib_suite_test.cf`, which has just **1** `test` block plus fuzz/bench blocks.
- About 115 inline programs embedded as C++ string literals across milestone-named test functions.

Concurrency coverage is 3 tests that string-match generated C++ (`scope.join_all();`), plus C++-level `sync::context` tests. There are no contention, stress, or race tests written in cfire.

What's missing is a **feature-organized, file-based corpus** of `.cf` programs that pins down language behavior: one file per expectation, readable on its own, runnable by `cfire test`, and with no C++ string-matching.

## 3. Proposed plan (new backlog IDs)

**Phase 14: Crash-proofing and the soundness net (1–2 days)**
- `CF-140` Replace every `.at()` in Sema with checked lookups that emit a diagnostic. Add a top-level `try/catch` around each LSP request and notification that returns an `InternalError` response instead of dying. Fixes A1.
- `CF-141` Wire `tests/fuzz/*` into `make fuzz-lib` + nightly CI. Add `fuzz_sema.cpp` (parse + analyze) and seed it with `examples/` and `tests/golden/`. Fixes E1.
- `CF-142` Add a `tests/unsound/` corpus with expected-reject or xfail status, covering A2–A8, B2, and D5. Fixes E2.

**Phase 15: Close the safety gaps (1–2 weeks)**
- `CF-143` Builtin method allow-list from the CF-117 metadata, with fix-its (`size`/`length` → `len`, `push_back` → `push`). Fixes B1 and A2.
- `CF-144` Loan provenance through return types (`&str`/`[]T` views returned from params), temporaries, struct fields, and map refs. Fixes A3–A6.
- `CF-145` Interface conformance check at generic call sites. Fixes A7 and fixes `examples/07`.
- `CF-146` Literal range checking and an `i32` condition-in-`if` error. Fixes A8 and part of B5.
- `CF-147` Unified slice-range semantics (panic) and a UTF-8 boundary decision. Fixes B2.

**Phase 16: Finish CF-116 and CF-118 for real (1–2 weeks)**
- `CF-148` Delete `infer_expr_type_name_sema`. Make TypeId the only inference path, with arg/field/method checks in Sema so clang never reports user type errors. Fixes B5 and B6.
- `CF-149` Emit `StructuredDiagnostic` objects directly with real columns and ranges. Delete `parse_diagnostic_string` and remove the duplicated code suffix. Fixes C1.

**Phase 17: Network and supply-chain hardening (1 week)**
- `CF-150` HTTP server: per-connection read/write deadlines, a bounded worker pool, strict `Content-Length` (reject invalid or duplicate), reject chunked requests or implement them, a peer address API, and IPv6. Fixes D1 and D7.
- `CF-151` Replace the `x-cfire-tls-*` magic headers with a typed `RequestOptions`. Fixes D2.
- `CF-152` Verify the cache against `build.lock` (commit and SHA) on every hit, use a per-user cache only, add `--` in git argv, use `curl --proto =https`, and move to `posix_spawn` argv. Fixes D3.
- `CF-153` `mkstemp`/`mkdtemp` everywhere in the runtime and CLI. Fixes D4 and E5.

**Phase 18: Uniformity and tooling polish (ongoing)**
- `CF-154` Decide the `::` vs `.` rule for type statics and pattern qualification. Rename `new_*` → `make_*`, and merge or rename the two `Mutex` types. Fixes B3, B4, and B7. Each of these needs a design decision from you.
- `CF-155` Scope-sound rename for closure params, fixed diff output, and subcommand `--help`. Fixes C2.
- `CF-156` Real AST pretty-printer plus an ugly→canonical corpus. Fixes C3 and E6.
- `CF-157` Make test-runner traps report the failing test and location. Fixes C4.
- `CF-158` `doc --check` rejects `file://` links, generates the diagnostics table from the code registry, and fixes the "rejected" wording. Fixes C5.
- `CF-159` CI: ASan on all suites plus Linux, a TSan job, the full runner on Windows, a non-phony `build`, and a hook that doesn't auto-stage. Fixes E3, E4, C6, and E7.

**Phase 14b: Conformance corpus, math, utilities, and concurrency safety**
- `CF-161` **`tests/conformance/` corpus.** One `.cf` per expectation, grouped by feature directory:
  - `syntax/`, `types/`, `ownership/` (move/loans/views), `errors/` (`T!`/`T?`/`try`/`or`/`defer`)
  - `match/`, `generics/`, `closures/`, `arith/` (overflow/div/narrowing)
  - `concurrency/` (scope join/defer ordering, channels close/drain/timeout, `Mutex[T]`/`Atomic` contention 8×10k, context cancel cascade, nested spawn, panic in task)
  - `stdlib/math`, `stdlib/str`, `stdlib/slices`, `unsound/` (xfail until CF-143/144/G1 land)

  Each file carries a header directive: `// expect: stdout <<EOF … EOF`, `// expect: error cfire/CODE @line`, `// expect: panic "<msg>"`, or `// expect: xfail CF-xxx`. A single harness runner (`make test-conformance`, part of `make test`) runs it, and the `concurrency/` directory also runs under TSan. The driver replaces C++ string literals; new language features must land with a conformance file. The ~115 inline programs migrate opportunistically.
- `CF-162` **Fill out `core:math`.** Add constants (`math.PI`, `math.E`; pick a constant form vs `pi()`), `pow`/`exp`/`log*`/rounding/trig/`hypot`/`atan2`, generic `min`/`max`/`abs`/`clamp[T]` (panic on lo > hi), `is_nan`/`is_inf`, `gcd`/`lcm`, Euclidean div/rem, and checked/wrapping/saturating for all integer widths plus `div`/`neg`. Remove `sqrt_f64` (DEPRECATED-API) and fix GUIDE line 199.
- `CF-163` **Uniform `str`/slice utilities.** Decide method vs free-function, apply it to the whole surface (the CF-143 allow-list is the natural place), and use one return convention: `T?` everywhere, no −1 sentinels. Add the missing slice basics (`contains`, `index_of`, `insert`, `remove`, `reverse`, `first`/`last` → `T?`, `is_empty`, `sort`) so the loan tracker can model them. Drop `str.find` from the reference.
- `CF-164` **Thread-safety rule for spawn captures.** Reject capturing `*mut T`, `&mut`, views, or non-`Mutex`/`Atomic`/`Channel` handles into `scope.spawn` unless the pointees are provably disjoint (for example, indexed slots from the loop variable). Add a `--sanitize=thread` mode and document the `Mutex[T]` guard pattern. Fixes G1–G3.

### Design decisions (resolved 2026-11-11)
1. **B1 (raw C++ container API):** reject it. Sema allow-lists cfire methods per builtin type (`str`, `[]T`, `[N]T`, `map[K]V`) from the CF-117 metadata table. Any other method is a new `cfire/UNKNOWN-METHOD` error, with fix-its for known synonyms (`size`/`length` → `len`, `push_back`/`emplace_back` → `push`, `substr` → slice, `empty()` → `len() == 0`). The raw C++ API stays available only inside `cpp {}` blocks. This also closes A2 (`CF-143`).
2. **B2 (slice ranges):** an invalid range panics with its source location, the same as indexing. That covers `lo > hi`, `hi > len`, and negative bounds. `str` slicing stays byte-indexed and zero-copy, but panics if either bound splits a UTF-8 code point (as in Rust). `CF-147`.
3. **B3 (separators):** amend ADR Q3. `::` is only for enum variant paths (`Enum::Variant`, `pkg.Enum::Variant`). `.` is for values, packages, fields, methods, *and* static functions on types (`http.Response.json(...)`). Patterns keep allowing unqualified variants. No migration needed; `CF-154` shrinks to naming (`new_*` → `make_*`, the two `Mutex` types) plus updating the ADR text in `backlog.md` §0.1.
4. **D6 (MCP scope):** confine every path-taking MCP tool to the server's workspace root. Paths are resolved via `weakly_canonical`, so `..` and symlink escapes are rejected, and `--allow-outside-root` is the opt-out. `cfire_eval` keeps executing code, but in a per-call `mkdtemp` directory. New item `CF-160`.
