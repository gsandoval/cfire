## Active Task: `ARCH-06` Invert Guide Documentation Pipeline

### 1. Scope & Problem Statement
- **Problem**:
  Currently, `docs/GUIDE.md` was generated by `cfire doc` from ~920 lines of markdown embedded in C++ raw string literals inside `src/docgen.hpp` (`generate_guide_markdown()`).
  Authors editing `docs/GUIDE.md` had their changes erased whenever `cfire doc` ran. Furthermore, `src/docgen.hpp` had another ~670 lines of hardcoded HTML for `generate_guide_html()`, resulting in ~1,600 lines of duplicated static text inside compiler source code.
- **In Scope**:
  - Invert the documentation pipeline: establish `docs/GUIDE.md` as the authoritative source file on disk.
  - Implement a fast, clean Markdown-to-HTML converter for the guide in `src/docgen.hpp`:
    - Reads `docs/GUIDE.md`.
    - Parses Markdown headers (`#`, `##`, `###`), paragraphs, lists, code fences (with syntax labeling: `cf`, `cpp`, `bash`, `json`), and blockquotes.
    - Generates dynamic sidebar navigation (extracting chapters and sub-headings).
    - Wraps content in the unified `cfire` responsive layout with navbar and CSS styling.
    - Emits `docs/guide.html`.
  - Remove the 920-line hardcoded `generate_guide_markdown()` literal from `src/docgen.hpp`.
  - Update `cfire doc` and `cfire doc --check` to read `docs/GUIDE.md` as input and compile `docs/guide.html`.
- **Out of Scope**:
  - Changing the standard library API documentation generation (`reference.html`, `STDLIB_REFERENCE.md`).

### 2. Open Questions & Architectural Clarifications
- **Source of Truth**: `docs/GUIDE.md` is strictly read-only for `cfire doc`; `cfire doc` never modifies `docs/GUIDE.md`.
- **Synchronization Check**: `cfire doc --check` verifies that `docs/guide.html` on disk exactly matches the HTML rendered from `docs/GUIDE.md`.

### 3. Testing Strategy Defined Across Tiers
- **Unit Tests**:
  - Markdown-to-HTML converter handles code blocks, nested headings, lists, inline backticks, and links correctly.
- **Integration Tests**:
  - `cfire doc` reads `docs/GUIDE.md` and generates `docs/guide.html`.
  - `cfire doc --check` passes cleanly.
- **Conformance Tests**:
  - `make review-check` passes all 4 quality gates.

### 4. Implementation Plan
- [x] **Step 1**: Implement `render_guide_markdown(std::string_view md_text)` in `src/docgen.hpp`.
- [x] **Step 2**: Update `generate_guide_html()` and `sync_docs_directory()` to read `docs/GUIDE.md` and compile `docs/guide.html`.
- [x] **Step 3**: Delete the 920-line hardcoded `generate_guide_markdown()` and 670-line `generate_guide_html()` string literals from `src/docgen.hpp` (-1,169 LOC).
- [x] **Step 4**: Run `cfire doc`, run `make review-check`, and verify 100% pass rate.
