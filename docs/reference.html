Compiler Semantic Diagnostics

[cfire/MUT-CALLSITE] — Missing Call-Site `mut` Marker

Functions declaring `mut param: T` mutate the caller's variable in-place (`T&`). Callers must write `mut arg` at the call site so mutation is visible when reading code.

Rejected (.cf)
fn bump(mut x: i32) { x += 1 }
fn main() {
    mut a := 10
    bump(a) // ERROR [cfire/MUT-CALLSITE]
}
Accepted (.cf)
fn bump(mut x: i32) { x += 1 }
fn main() {
    mut a := 10
    bump(mut a) // OK
}

[cfire/OUT-CALLSITE] — Missing Call-Site `out` Marker

Functions declaring `out param: T` initialize or overwrite an output parameter (`T&`). Callers must write `out arg` at the call site.

Rejected (.cf)
fn write_sum(out total: i32) { total = 42 }
fn main() {
    mut s: i32 = 0
    write_sum(s) // ERROR [cfire/OUT-CALLSITE]
}
Accepted (.cf)
fn write_sum(out total: i32) { total = 42 }
fn main() {
    mut s: i32 = 0
    write_sum(out s) // OK
}

[cfire/IMMUTABLE-MUT-ARG] — Passing Immutable Binding as `mut` or `out` Argument

Bindings declared with `:=` or `x: T = ...` without `mut` are `const` by default and cannot be passed to `mut` or `out` parameters.

Rejected (.cf)
fn reset(mut v: i32) { v = 0 }
fn main() {
    val := 5
    reset(mut val) // ERROR [cfire/IMMUTABLE-MUT-ARG]
}
Accepted (.cf)
fn reset(mut v: i32) { v = 0 }
fn main() {
    mut val := 5
    reset(mut val) // OK
}

[cfire/MUT-RECEIVER] — Calling `mut` Method on Immutable Receiver

Methods with a mutable receiver `fn (mut self: Counter) inc()` cannot be invoked on an immutable binding.

Rejected (.cf)
c := Counter{Value: 0}
c.inc() // ERROR [cfire/MUT-RECEIVER]
Accepted (.cf)
mut c := Counter{Value: 0}
c.inc() // OK

[cfire/MUT-ALIAS] — Mutable Aliasing Across Call-Site Arguments (Law of Exclusivity)

A variable passed as a `mut` or `out` argument (or used as a `mut` method receiver) cannot also be passed as another argument in the same call.

Rejected (.cf)
fn transfer(mut from: i32, mut to: i32) { ... }
fn main() {
    mut acc := 100
    transfer(mut acc, mut acc) // ERROR [cfire/MUT-ALIAS]
}
Accepted (.cf)
fn transfer(mut from: i32, mut to: i32) { ... }
fn main() {
    mut a := 100
    mut b := 50
    transfer(mut a, mut b) // OK: distinct bindings
}

[cfire/USE-AFTER-MOVE] — Use of Value After Explicit `move`

Once a variable is passed with `move x` (which lowers to `std::move(x)`), reading or passing `x` again in the same scope is rejected at compile time.

Rejected (.cf)
consume(move buf)
println("{}", buf.len()) // ERROR [cfire/USE-AFTER-MOVE]
Accepted (.cf)
println("{}", buf.len())
consume(move buf) // OK: moved on last use

[cfire/NON-EXHAUSTIVE-MATCH] — Non-Exhaustive `match` Statement Over Algebraic `enum`

Every `match` over a `type ... enum` must either cover all declared variants or include a wildcard `_ => { ... }` arm.

Rejected (.cf)
match shape {
    Circle(r) => { ... }
    // ERROR [cfire/NON-EXHAUSTIVE-MATCH]: missing Rect
}
Accepted (.cf)
match shape {
    Circle(r) => { ... }
    Rect(w, h) => { ... }
}

[cfire/NON-DIVERGING-OR-BLOCK] — Non-Diverging Error Recovery Block on Value Binding

When initializing or assigning a variable with `val := fallible() or err { ... }`, the error recovery block must definitely diverge with `return`, `panic(...)`, or `exit(...)` to avoid unwrapping an uninitialized value.

Rejected (.cf)
fn compute() -> i32 {
    // ERROR [cfire/NON-DIVERGING-OR-BLOCK]: handler does not diverge
    x := parse_num() or err {
        println("error: {}", err.message())
    }
    return x
}
Accepted (.cf)
fn compute() -> i32 {
    x := parse_num() or err {
        println("error: {}", err.message())
        return 0
    }
    return x
}

[cfire/DEPRECATED-OUT-PARAM] — Deprecated `out` Parameter Intent (Favor Multi-Return Tuples)

The `out` parameter intent is deprecated in favor of multi-return tuples `fn parse() -> (f64, f64)!` and deconstructing assignments `(x, y) := parse()`. `out` parameters bypass definite assignment checks and hinder expression composition.

Rejected (.cf)
fn parse_coords(s: str, out x: f64, out y: f64) { ... } // WARNING [cfire/DEPRECATED-OUT-PARAM]
Accepted (.cf)
fn parse_coords(s: str) -> (f64, f64)! { return (1.0, 2.0) }
(x, y) := try parse_coords("1,2") // OK

[cfire/DEPRECATED-VAR] — Deprecated `var` Keyword (Favor Canonical `:=` or `: Type =`)

The `var` keyword is deprecated in favor of canonical inferred declarations `x := val` / `mut x := val` and explicitly typed declarations `x: T = val` / `mut x: T = val`.

Rejected (.cf)

Accepted (.cf)

mut name: str = "hello" // OK
